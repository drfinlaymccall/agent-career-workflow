# Contributing

Use entirely invented examples in issues and pull requests. Do not lightly anonymise a real candidate's history.

1. Explain the behaviour and privacy boundary being changed.
2. Add positive and negative tests, including the relevant failure path.
3. Run the unit tests and privacy checker.
4. Run the documented demo in a new private sibling directory.
5. Review the diff and archive manifest before release.

Prefer Markdown source records and rebuildable projections over a second authoritative database.
Keep human approval gates, source uncertainty and failure reporting visible.
Do not claim hiring gains, ATS guarantees or full market coverage without defensible evidence.
Keep vendor-specific adapters optional. Do not add automatic sending or application submission as a default.

Code and documentation are provided under the MIT licence. Only contribute material you have the right to share.
